# YouTube Notes

YouTube動画の字幕から、**動画を見なくても中身が追える詳細メモ**を日本語で作る。
要約(圧縮)ではなく、話の流れを保ったまま読める形に再構成するのが目的。

## 詳細さの基準

- 迷ったら残す。主張は**根拠とセット**で書く
- 固有名詞・数値・具体例・引用は原則すべて拾う
- 章立ては**動画の進行順**に従う。トピック単位で再編集しない
- 分量の目安は字幕の 1/4〜1/3。1/10 を切っていたら削りすぎ
- 動画で語られていない内容を足さない。ただし字幕の誤変換を直すのは「足す」ではなく
  復元なので、フロー4に従って遠慮なく直す。字幕から読み取れない補足を書くときは
  `(注: ...)` と明示する
- 「短く」「要約だけ」と明示的に頼まれたときのみ、末尾の簡易サマリだけを返す

## フロー

1. **字幕取得**: セッションのスクラッチパッドを出力先にしてスクリプトを実行する:

   ```
   python <このスキルのベースディレクトリ>/scripts/fetch_transcript.py "<URL>" --out "<スクラッチパッド>/youtube-summary"
   ```

   成功時(exit 0)はstdoutにメタデータJSONが出る:
   `title` / `channel` / `duration_human` / `language` /
   `subtitle_type`(manual|auto|translated)/ `transcript_path` / `char_count`

2. **エラー分岐**(stderrの `ERROR:<CODE>` と終了コードで判定):
   - `YTDLP_MISSING`(exit 3): `pip install yt-dlp` を実行して**1回だけ**リトライ
   - `NO_SUBTITLES`(exit 2): 「この動画には字幕がないためまとめられない」と報告して終了。
     内容を推測・捏造しない
   - `VIDEO_UNAVAILABLE`(exit 4): 非公開・年齢制限・地域制限等で取得できない旨を
     エラー内容とともに報告して終了
   - その他(exit 1): **1回だけ**リトライし、2回目も失敗したらエラー内容を報告して終了。
     無限リトライ禁止

3. **transcript読み込み**: `transcript_path` のファイルを全文読む。
   `char_count` が **80,000 を超える**場合は Read の offset/limit で分割して読み、
   **チャンクごとに詳細メモを書いて順に連結する**。
   中間要約に圧縮しない(一度圧縮すると後段で情報を復元できない)

4. **聞き取りミス補正**: 文脈から明らかな誤認(同音語の取り違え、固有名詞の表記揺れ)は
   黙って直した内容でまとめる。確信が持てない重要語のみ「(原文: ○○)」と注記する。
   補正箇所の一覧は出さない。
   同じ固有名詞が動画内で表記ゆれしている場合は、最も確からしい表記に統一する。
   数値の聞き取りミス(桁・単位)は本文で目立つので特に注意する

5. **保存するかの判定**: このスキルの `config.yaml` を読む。
   `always_save` が true、または「保存して」と頼まれた場合は**保存する**。
   どちらでもなければ保存しない

6. **出力**: 動画が何語でも**日本語**で出力する。保存の有無で出し分ける:
   - **保存しない場合**: 下の詳細テンプレをチャットに全文出力して終了
   - **保存する場合**: 詳細テンプレの全文は**ファイルに書き**、チャットには
     章立てと要点だけを返す(「保存する場合のチャット出力」を参照)。
     同じ長文を二度出さない

## 詳細テンプレ(本文)

```markdown
## <動画タイトル>
<チャンネル名> / <長さ> / <字幕種別: 手動字幕 or 自動生成字幕>
※字幕に音声認識由来の誤変換が多く、文脈から補正しています。
固有名詞などに誤りが残っている可能性があります
(↑この注記行は**フロー4で補正を何度も行った場合**に出す。`subtitle_type` では判定しない。
手動字幕として投稿されていても中身が音声認識出力で、誤変換だらけのことがある)

**この動画の主張**
3〜5文。全体の結論を先に置く。

---

### 1. <章タイトル>
本文。段落または箇条書き。根拠・具体例・数値をそのまま含める。

### 2. <章タイトル>
...

(章数は動画の構成に従う。目安は10分あたり1〜3章)

---

**押さえておく点**
- 後から参照する価値のある事実・数値・固有名詞を箇条書き

**所感**
2〜3文。
```

## 保存フォーマット

保存先・ファイル名・frontmatter は `config.yaml` の値に従う。
本文は詳細テンプレをそのまま使い、先頭に frontmatter と出典ブロックを付ける:

```markdown
---
updated: <保存日 YYYY-MM-DD>
status: done
tags: [<動画の内容から3〜6個>]
---

# <動画タイトル>

出典: <動画URL>
「<動画の原題そのまま>」
<チャンネル名> / <長さ> / <YYYY-MM-DD 視聴>

※(詳細テンプレと同じ条件で、補正を何度も行った場合のみ注記行を入れる)

<以降、詳細テンプレの「この動画の主張」以下をすべて>
```

## 保存する場合のチャット出力

ファイルに全文を書いたら、チャットには**同じ長文を繰り返さない**。代わりに:

```markdown
保存しました → `<保存したファイルのパス>`(<サイズ>)

## <動画タイトル>
<チャンネル名> / <長さ> / <字幕種別>

**この動画の主張**
詳細テンプレと同じ3〜5文。

**章立て**
- 1. <章タイトル> — 1行で中身
- 2. <章タイトル> — 1行で中身
(全章を列挙する。ファイルのどこに何があるか分かるように)

**特に効く点**
- 詳細メモの中から、実務で使える・意外性のある点を3〜5個
```

読み返すのはファイル側なので、チャットは「何が入っているか」と
「どこを読むべきか」が分かれば足りる。

保存時の注意:

- 既定の保存先は `life` リポジトリの参照メモ置き場。そこの規約に従うため、
  ファイル名に日付は付けず、**出典URLを必ず残す**
- 同名ファイルが既にある場合は上書きせず、内容を確認してから追記か別名かを判断する
- 保存したら**ファイルパスをユーザーに伝える**

## 注意

- プレイリストURLでも対象は動画単体(`v=` の動画のみ)。一括まとめはしない
- 字幕なし動画への音声認識フォールバックはスコープ外
- 長い動画では出力も長くなる。それは仕様であって、勝手に短くしない
